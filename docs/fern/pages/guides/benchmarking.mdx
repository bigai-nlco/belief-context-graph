The reference Agent can evaluate **BrowseComp** and its Chinese-language counterpart, **BrowseComp (ZH)**, in Default mode, BCG mode, or both. The same Agent model, prompt, tool policy, task selection, and scorer are used for both modes; only context management changes. This isolates the effect of graph-backed context from every other variable.

<Note>
Benchmarking runs the bundled reference Agent, not the Python SDK or HTTP construction service directly. It is a way to evaluate BCG's effect on that Agent, not a required step for integrating BCG.
</Note>

## 1. Prepare the datasets

Place dataset files under one root:

```text
datasets/
├── browse_comp/data.json
└── browse_comp_zh/data.json
```

JSON, JSONL, and CSV are supported without extra packages. Parquet input requires:

```bash
uv sync --extra benchmarks
```

Each path may instead be supplied explicitly with a repeatable `--data-file BENCHMARK=PATH` option.

<Info>
The official BrowseComp dataset encrypts each question and answer behind a canary string, precisely so it can be used to detect contamination in training data. Treat both variants accordingly — see the Git warning under [Output artifacts](#output-artifacts).
</Info>

## 2. Configure the Agent and web search

Benchmarking reuses the same credentials as the terminal Agent. Set them in `~/.bcg/.env` (written by `bcg setup`) or the current environment:

```bash
OPENAI_BASE_URL=https://your-openai-compatible-server/v1
OPENAI_API_KEY=...
OPENAI_MODEL=your-agent-model
SERPER_API_KEY=...  # required for BrowseComp and BrowseComp (ZH)
```

## 3. Run a comparison

```bash
bcg benchmark run browsecomp browsecomp_zh \
  --modes default,bcg \
  --thinking off \
  --max-problems 100 \
  --workers 8 \
  --output-dir results/browsecomp-comparison
```

This runs the same selected examples in both context modes.

<Info>
Use `--thinking medium` (or another supported level) to set the Agent's reasoning effort for the run. This setting is independent of the Graph Construction model's `pipeline.extractor.enable_thinking` and `pipeline.edge_generation.enable_thinking` settings — see [Configuration](/reference/configuration).
</Info>

## How BCG mode reaches the Graph server

When BCG mode is requested, the command reuses a healthy Graph Construction server or starts the configured local server the same way `bcg` does — see [Managed Graph Construction](/guides/reference-agent#managed-graph-construction).

<Warning>
A BCG request that falls back to raw context is marked `graph_fallback` and excluded from accuracy by default. Use `--allow-graph-fallback` only when that behavior is intentional; otherwise a struggling Graph server will silently understate BCG's effect rather than fail loudly.
</Warning>

## Scoring

Both variants are scored the same way:

| Benchmark | Scoring |
| --- | --- |
| BrowseComp | Official-style binary LLM judge |
| BrowseComp (ZH) | Official-style binary LLM judge, Chinese-language questions and answers |

Both use the Agent model and endpoint as the judge by default. Override it with `--judge-model`, `--judge-base-url`, and `--judge-api-key-env`.

## Output artifacts

Every task runs in an isolated working directory. Artifacts are resumable and contain:

```text
<output-dir>/
├── run.json
├── summary.json
└── <benchmark>/<mode>/
    ├── tasks/<task-id>.json
    └── trajectories/<task-id>.jsonl
```

<Warning>
Dataset files and benchmark results are ignored by Git because task artifacts contain plaintext questions, model responses, and reference answers. Do not publish them unless the dataset's license and benchmark policy explicitly allow it.
</Warning>

## Reading `summary.json`

`summary.json` separates Agent input, output, cache-read, cache-write, reasoning, and total tokens. Judge input/output tokens are reported separately when the judge endpoint returns usage. It also records:

- wall time;
- tool/search call counts;
- model-reported Agent cost;
- status counts;
- benchmark-specific metrics.

Timeout, max-token, Agent error, and judge failure attempts count as incorrect in the primary accuracy; Graph fallbacks are excluded. A separate completed-only accuracy is retained for diagnosis.

<Info>
See every option with `bcg benchmark run --help`. Published results from this Agent/backend setup are in the top-level [README](https://github.com/bigai-nlco/belief-context-graph#benchmarking-results).
</Info>
