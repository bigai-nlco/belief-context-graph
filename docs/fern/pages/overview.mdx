BCG adds an **auditable belief layer** to an agent or application. It converts a trajectory into structured knowledge that can be inspected, queried, updated, and traced back to its source.

Most memory systems are optimized for retrieval: *what was said, what is similar, what is related?* BCG focuses on the next questions:

- What does the system currently believe?
- How confident is it?
- Which source text supports it?
- What depends on or contradicts it?
- Which conclusion or decision did the agent reach?
- What should be passed back into the next model call?

## What BCG produces

A completed run can contain:

- **knowledge nodes** for beliefs and decisions;
- **source information** that links a node back to the trajectory;
- **confidence state and history**;
- **typed connections** between nodes;
- **merge history** for duplicate or near-duplicate knowledge;
- **session and timing metadata**;
- **JSON and JSONL artifacts** for inspection, replay, or downstream processing.

<Note>
BCG is not an agent framework and does not require the bundled terminal Agent. You can use the Python SDK or HTTP service beneath your own runtime.
</Note>

## Project boundaries

BCG persists run artifacts to files and keeps active HTTP construction sessions in process memory. The repository does not provide a production graph-database adapter, distributed session coordinator, or hosted control plane. Add those infrastructure concerns around BCG when your deployment needs them.
