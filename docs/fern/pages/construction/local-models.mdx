The code identifier for this backend is:

```text
hybrid
```

The current pipeline uses:

- a small generative model through an OpenAI-compatible vLLM endpoint;
- a local sentence-transformers embedding model;
- a local/Hugging Face stance classifier;
- spaCy for local language processing and entity extraction.

## Start vLLM separately

BCG does not install or manage the external vLLM GPU service for you.

Example source setup:

```bash
uv venv ~/.bcg/vllm --python 3.11
uv pip install --python ~/.bcg/vllm/bin/python vllm

~/.bcg/vllm/bin/vllm serve <MODEL_OR_LOCAL_PATH> \
  --served-model-name <MODEL_NAME> \
  --host 127.0.0.1 \
  --port 8001 \
  --max-model-len 10000 \
  --max-num-seqs 8
```

<Info>
For source development, `scripts/start_vllm.sh` is also available, but it reads `VLLM_*` values from the checkout's root `.env` or explicit command-line arguments; it does not read `~/.bcg/config.yaml`.
</Info>

## Using this backend with the terminal Agent

Once vLLM is serving, configure BCG with:

```text
Graph server: Start and manage a local Graph server automatically
Graph backend: Local model construction (hybrid)
vLLM base URL: http://127.0.0.1:8001/v1
Model served by vLLM: <MODEL_NAME>
vLLM API key: EMPTY
```

`<MODEL_NAME>` must match the value passed to `--served-model-name`. After vLLM is ready, launch the Agent:

```bash
bcg
```

BCG starts the `hybrid` Graph Construction server at `127.0.0.1:8848`; it does not start the vLLM process itself.

## Manual server (independent deployment or debugging)

Configure the matching endpoint/model in `~/.bcg/config.yaml` and run:

```bash
bcg construct server hybrid \
  --config ~/.bcg/config.yaml \
  --model-key graph-model \
  --embedding-key embedding \
  --host 127.0.0.1 \
  --port 8848 \
  --output-dir ~/.bcg/graphs
```

<Info>
The hybrid CLI intentionally exposes fewer one-off run flags than the API-model path. Treat the unified YAML pipeline settings as the source for full backend configuration.
</Info>
