The code identifier for this backend is:

```text
unified
```

Use it when an OpenAI-compatible model endpoint is already available.

## Using this backend with the terminal Agent

During `bcg setup`, API model construction can reuse the Agent's own model endpoint and API key, or use a separate endpoint:

```bash
bcg setup
# Graph server: Start and manage a local Graph server automatically
# Graph backend: API model construction (unified)

bcg
```

No separate vLLM process is required when the configured API endpoint is already available. If a server for this backend is already healthy, a later `bcg` invocation reuses it instead of starting a new one.

## Server

```bash
bcg construct server unified \
  --config ~/.bcg/config.yaml \
  --model-key graph-model \
  --embedding-key embedding \
  --host 127.0.0.1 \
  --port 8848 \
  --output-dir ~/.bcg/graphs
```

## Construction modes

This backend has two switchable implementations, set with `pipeline.runtime.construction_mode` in `~/.bcg/config.yaml`:

```yaml
pipeline:
  runtime:
    construction_mode: llm  # canonical/default implementation
  token_efficient:
    max_search_results: 10
    max_snippet_chars: 240
    semantic_tool_results: true
    max_facts: 3
    max_semantic_calls: 12
```

- **`llm`** (default) is the canonical model-extraction and model-linking implementation described above.
- **`token_efficient`** parses canonical Agent tool calls and tool results in code, distills a bounded number of non-empty tool results with a short current-query-only prompt, creates provenance edges deterministically, and uses embedding-only merge without LLM verification. Raw tool output remains attached as evidence. After `max_semantic_calls`, later tool results automatically fall back to the zero-LLM rule path; set `semantic_tool_results: false` to use that path from the start.

Restart the Graph Construction server after changing `construction_mode`.

<Note>
This setting controls how the Graph is *built*. How much of it gets *rendered* into the Agent's context (`full` vs `compact`) is a separate, independent setting — see [Graph presentation](/guides/reference-agent#graph-presentation-full-vs-compact).
</Note>

## Python

```python
runner = BCGRunner(
    memory=memory,
    llm=llm,
    backend="unified",
)
```

Relevant runner controls include:

```python
evidence_mode="sentence"
incremental_merge=True
incremental_merge_threshold=0.86
verify_merge=True
context_chars=100000
io_context_chars=6000
min_content_len=0
```

These are exposed by `observe_trajectory()` / `begin_belief_run()` and may also be configured through the unified YAML settings.

## Configuration

Model and embedding endpoint definitions live in the unified `config.yaml` model registry. Use:

```bash
bcg config
```

to confirm which values are actually active.
